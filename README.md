# Quick Route Next

[公開アプリ](https://anemia111.github.io/quick-route/) · [リポジトリ](https://github.com/anemia111/quick-route)

登録した2駅へ、ホームから1タップ。全国駅候補、許諾済み時刻表の自動保存、対応区間の端末内経路計算、表示中の移動モードを備えるReact・TypeScript・ViteのiPhone向けPWAです。GitHub Pagesの静的配信を維持し、有料API・サーバー・ログイン・アクセス解析を追加していません。公開アプリの内容はmainのデプロイ時点に依存します。

## できることと対応範囲

- 青いボタンは「登録した目的地駅へ」、緑は「登録した最寄り駅へ」。長い駅名、小さい画面、ライト／ダーク、セーフエリアに対応。
- 全国駅データ10,154レコード。国土交通省N02-2025（2025年末基準）の加工版。会社・路線の候補を表示し、同名駅はIDで区別。2026年の全変更・全駅のカナ読みは未確認／未対応。
- 都営交通6系統の実GTFSを収録。合計5,600trip、約4.46MB、版20260921、有効20260314〜20270312。路線別に配信し、登録駅・最近の利用・頻度・関連する代替路線に応じてIndexedDBへ保存。
- CSAで実際の列車時刻・運行日・例外日・24時超・乗降条件を計算。候補は**収録データ内**の比較。時刻表に乗換時間がないため、初期の実データでは主に同じ列車で移動できる区間を検索。未確認の乗換や全国最速を装いません。
- キー不要の都営TripUpdatesを取得できた列車は、公式の発着予測・運休を反映。通常ダイヤ、以前の予測、現在未取得を区別。列車IDだけでなく運行日も照合。
- 選択経路を明示操作で追跡開始・終了。表示中のみ更新し、現在駅の確認後に代替候補を評価。GPSは別の操作で許可を求め、拒否時も手動確認を利用。変更は利用者が承認するまで実行しません。
- データ不足時は既存のYahoo!乗換案内へ引き継ぎます。遷移の瞬間の日本時刻、出発指定、到着が早い順を維持。オフラインで不足する場合はその理由を表示。

JR線を含む全国の完全な独自時刻表検索、全国の乗換時間、異なるパッケージ間の乗換、異なるtrip IDをまたぐ直通、全国RT、路線Alertの汎用取り込み、過去遅延の確率予測、背景での継続追跡・OS通知は未対応です。将来what-ifを区別する関数はありますが、根拠のない将来予測をUIで有効化していません。

## 起動・検証

Node.js 24とnpmを使用します。

```sh
npm ci
npm run dev
npm run typecheck
npm test
npm run lint
npm run build
npx playwright install chromium webkit
npm run test:e2e
npm run preview
```

開発・プレビューURLの `/quick-route/` を開きます。新しい設定画面は増やさず、既存の2駅設定画面に候補を追加しました。iPhoneのSafariで開き、共有メニューから「ホーム画面に追加」してください。Safariとホーム画面PWAの保存領域が異なる場合があります。

## 保存・更新とプライバシー

既存 `quick-route.stations.v1` を維持し、候補を選んだ設定に任意の駅IDを追加。検索履歴は端末内100組まで。位置座標をサーバー送信・永続記録しません。Yahoo!検索時は駅名と日時が同サービスへ送られ、データ取得先には通常のHTTPリクエストが発生します。

時刻表は必要な単位で取得し、サイズ・SHA-256・構造・版・有効期間の検証完了後に原子的に置換。容量はStorage APIから自動判断し、期限切れ・低優先度・未使用の順で整理します。API未対応時は暫定16MiB、最大64MiB。保存の永続性はOS・ブラウザに依存し、保証しません。消失時は外部検索と再取得で復旧します。

アプリ起動・設定変更・検索後に公開manifestの版を確認します。元事業者のGTFS変更をそのまま無審査で取り込む構成ではありません。公開パッケージの更新は下記の保守手順で行います。現在は変更パッケージ単位の完全取得で、汎用のバイナリ差分配信は未対応です。

## データ更新の保守手順

1. [調査資料](docs/STEP-0A-DATA-RESEARCH.md)の公式URLと、対象ファイルのライセンス・特定条件を再確認。
2. Python 3（標準ライブラリのみ）で `python scripts/prepare_data.py`。公式公開ZIPを前処理し `public/data/` とmanifestのハッシュを更新。通過駅の時刻を推定補間しない。
3. 全検証を実行。実データテストの日付は収録版の有効期間内に保ち、旧版と新しいダイヤの差を確認。
4. PRで版・有効期間・対応範囲・出典の差分をレビューしてmainへ反映。

N02の次年度版を導入するときはURLと基準年を明示的に更新し、許諾を再確認。全国表は `python scripts/coverage_report.py` で再生成できます。調査日・個別確認日は自動で最新と装わず、調査時に更新してください。

## 自動検証・デプロイ

PRの `check.yml` は型チェック・40件の単体／結合テスト・Lint・本番ビルド・PlaywrightのChromium／WebKit検証を実行。mainの既存 `deploy.yml` はLintも含め検証後にGitHub Pagesへ配信します。base・Manifest・Service Workerは `/quick-route/`。Service Workerの更新でIndexedDBや駅設定を消去しません。

公開データには国土交通省、東京都交通局・公共交通オープンデータ協議会のCC BY 4.0データを使用し加工しています。[ソフトウェアのライセンス](public/licenses.txt)も同梱。APIキーは不要でフロントエンドに秘密情報を埋め込んでいません。ODPT基本ライセンス・期間限定ライセンスのデータはこの配信に収録していません。
