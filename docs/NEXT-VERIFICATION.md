# Quick Route Next：実装・検証記録

確認日：2026-10-01（日本時間）。対象は `codex/quick-route-next`。旧版の基準commitは `734876d`。コードの実装範囲と、利用できる実データの範囲を分けて記録する。

## 実装済み

- 全国駅候補、同名駅のID区別、会社・路線表示。既存の2駅設定を引き継ぎ、駅名に連動するホームボタンから往復検索。
- 共通鉄道モデル、公式データの前処理、路線別配信、IndexedDBの取得・保存・再利用・更新・削除。
- 登録駅、端末内の検索頻度・最近の利用、関連路線による自動保存。Storage APIに基づく自動容量管理。起動時の公開manifest更新確認。
- CSAによる実時刻・運行日・例外日・24時超・乗降条件・確認済み乗換時間の計算。Web Workerへ処理を分離し、対象外パッケージの転送・走査を省く。
- 都営の公開TripUpdatesの正規化、鮮度確認、個別予測・運休反映、乗換失敗分析。通常ダイヤ・公式予測・未取得・明示what-ifを区別。
- 明示開始・終了、表示中の再評価、任意の位置許可、現在駅の手動確認、重要変更のアプリ内通知、承認による経路変更、復帰時の状態復元。
- 320px、長い駅名、ライト／ダーク、セーフエリアへの対応。PR検証workflowと既存GitHub Pages配信を維持。

## 実データの範囲

全国駅候補は国交省N02-2025の10,154レコード（駅コード単位、実際の駅施設数とは異なる）。2025年末基準であり、2026年の新駅・名称変更をすべて含むとは保証しない。全国表の597組・177事業者名文字列も現在の法人数や運転系統数ではない。

時刻表は東京都交通局・公共交通オープンデータ協議会のCC BY 4.0 GTFSを加工した6パッケージ（浅草・三田・新宿・大江戸・日暮里舎人・荒川）、5,600trip、版20260921、有効20260314〜20270312。時刻未記載の通過点540行は乗降不可の場合だけ省略し、時刻を推定補間していない。

元ファイルに乗換時間がないため、実運用は主に同一列車で移動する区間。別路線への乗換を未確認の徒歩時間で作らない。同一trip内の直通は扱うが、異なるtrip IDの直通関係、他社へ出た先、異なるパッケージ間の乗換は未対応。大江戸線の実データでは709tripに駅IDの再訪があり、停車順序・日時を経路IDに含め、後の周回で最初の到着を上書きしない。

都営TripUpdatesは認証なしGETとCORS `*` を確認。実応答をデコードし、2026-10-01 17:02:11 JST生成のサンプルで収録tripに照合できる91件を確認した。これは当日の応答例であり、すべての列車・路線で常時予測が得られるという意味ではない。路線全体のAlert、列車位置、全国の運行情報、過去の遅延実績はアプリに収録していない。

公式リソース・条件・GET確認記録は [調査](STEP-0A-DATA-RESEARCH.md)、[全国表](NATIONAL-COVERAGE.md)、[取得記録](source-probes.json)を参照。

通常運行、確認済み乗換、終電、日付変更、運行日例外、同一trip直通、乗降禁止、時刻表不足、運休、予測時刻による乗換失敗を単体テスト。架空データはテストファイル内に限定。実GTFS6ファイルの検証、浅草線の実時刻、大江戸線の同一駅再訪を別に検証した。全列車・全日付の事業者ダイヤとの突合は未実施。

運行情報のstop_sequenceが照合できない場合は影響分析を有効化しない。遅延値は通常ダイヤを基準に適用し、既に遅延を含む経路へ重ねて加算しない。追跡していない画面でも公式予測の期限切れ表示を更新する。現在駅の確認は代替再計算に2分間だけ使用し、復帰時には再確認する。

Windows WebKitでは `context.setOffline` 後のページ再読み込みが内部エラーになるため、その検証を成功とは記載しない。Linux CIではWebKitの再読み込みも検証対象。デスクトップWebKitの成功をiPhone実機の成功と扱わない。

経路計算は全6パッケージを入力し、西馬込→馬込、2026-10-01 08:00 JST、候補8件。最終版は両端を扱えるパッケージに絞ってWorkerへ渡す。複数路線・全候補の最大負荷の測定ではない。全国駅候補は100msの入力待ち合わせと初回読込を含む。

メインJS246,808 bytes（gzip77,793 bytes）、RTモジュール119,623 bytes（gzip33,186 bytes）。駅データ1,309,704 bytes、時刻表合計4,464,442 bytesをホームの描画前には必須にしない。JSのPWA事前保存が増えるため初回通信量は旧版より増加する。RTは画面側から必要時に読み込むがSW事前保存に含む。データJSONは事前保存せず、必要な単位でIndexedDBへ取得。

5秒待機中のメインスレッド処理4.16ms。測定ページには全時刻表を注入しておりJS heap約70.5MBはその条件の値で、iPhoneや通常ホームの使用量ではない。別の65秒の追跡試行ではメインスレッド44.1ms、RT取得試行1回、heap約49.9MB。GPSなし・現在駅未確認・RT取得を意図的に失敗させた条件で、位置追跡や代替計算が頻繁に発生する場合の評価ではない。電池消費・CPU全体・端末最大メモリは未測定。

生の値：[最終測定](performance.json)、[最適化前](performance-before-optimization.json)、[追跡試行](performance-tracking.json)。再測定には旧版previewを4174、最終版を4173で起動して `npm run bench`。ビルドや別のブラウザテストを同時に動かさない。

## 残る条件と保守

- iPhone実機のSafari／ホーム画面、実移動、GPS不良の実測、OS更新後の保存、バックグラウンド復帰、電池消費は未検証。画面非表示中の継続追跡・通知を保証しない。
- 全国時刻表・全国の乗換時間・全国リアルタイムがそろわない。未確認の事業者を「公開なし」と結論づけない。未対応区間はYahoo!へ、通信断時は不足理由を表示。
- 保存の永続性は保証できない。駅設定と時刻表を別に扱い、保存消失時には再取得する。期限切れの時刻表は最新ダイヤとして使用しない。
- 公開manifestの変更は自動検出するが、元GTFSの改正を公開データへ反映する作業は保守者のレビューが必要。差分は変更パッケージ単位であり、バイナリ差分配信は未対応。
- 過去遅延に基づく確率予測、路線遅延を個別列車へ割り当てる処理、将来シミュレーションUI、背景OS通知は有効化していない。
- 全国経路の厳密な最適性を保証しない。探索は候補数・ラベル数を制限する。全国拡張時には不足データの取得だけでなく、性能・探索境界・直通ID・乗換接続の再検証が必要。
- PR検証workflowを追加。既存mainのPagesデプロイは維持しLintを追加。今回の変更はレビュー用ブランチで、公開済みアプリへの反映状況はGitHubのmainとデプロイ履歴で確認する。
