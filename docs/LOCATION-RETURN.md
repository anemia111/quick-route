# 現在地から帰る：位置検出と検索

実装日：2026-10-02 JST。既存の駅設定・東京／新宿の入力例・往復ボタンを維持する。

「現在地から帰る」→必要なら位置許可→近くの駅を選択→登録した最寄り駅への検索。帰宅先は従来の「最寄り駅」。独立した帰宅先の設定は増やさない。検出した駅で登録駅を書き換えない。

## 検出精度

- `watchPosition` を明示操作時にだけ開始。`enableHighAccuracy: true`、`maximumAge: 0`。取得を待つのは最大15秒。
- 新鮮な複数位置が届いた場合、APIの報告するaccuracyが最も小さい位置を採用。accuracyが30m以下なら早く終了。30m以下の実精度を保証する意味ではない。
- 位置の生成が30秒より古い、範囲外の緯度経度、非数値、誤差200m超なら採用しない。期限までに有効な位置を得られない場合は失敗を表示。
- 終了・キャンセル・非表示・別の検索や追跡開始・コンポーネント破棄でwatchを停止。遅れて届いた結果は破棄。OSの位置測定や誤差推定そのものの正確性はアプリでは保証できない。
- 国交省N02の駅の点との球面距離を計算。5km以内の近い順に最大3候補。同名で近接する駅レコードをまとめ、選択したレコードのIDで独自時刻表へ照合する。
- 位置誤差を候補に表示。検出から60秒を超えて選択する場合は再取得を要求する。

## 検索の正確性と限界

駅への直線距離は入口や歩道の経路ではない。最も近い駅と、最も早く帰れる駅は一致するとは限らない。入口・徒歩時間・構内移動時間の確認できるデータを現在は収録していないため、徒歩時間を作って列車に間に合うと断定しない。

利用者が出発する駅を選び、その駅から通常の検索機能へ引き継ぐ。対応区間では収録データのCSA候補を表示し、未対応ではYahoo!乗換案内の出発時刻・到着が早い順を維持。遷移の瞬間に時刻を取得する。複数の駅からの全国経路や徒歩を含む帰宅時間の自動比較は未対応。

位置座標はメモリ内のみで処理。アプリから座標を送信・保存しない。端末内の通常検索履歴には駅名の組合せが残る。Yahoo!利用時は、確認して選んだ駅名・帰宅先・日時が同サービスへ渡る。OSやブラウザ自身の位置情報サービスは、各設定・許諾に従う。

オフラインでは保存済み駅データで候補を探せる。駅データ未保存・破損等なら取得失敗を表示。保存済みの有効な時刻表がない区間は、通信復帰までYahoo!検索を利用できない。位置拒否・GPS不良でも既存の往復ボタンや駅設定は利用可能。

## 検証

単体・結合53件：球面距離、重複候補、遠い駅、異常座標、許可拒否、精度不足、古い位置、最良サンプル、15秒終了、高精度設定、GPS停止、キャンセル、選択前の鮮度、通信断、設定保持を含む。

ブラウザ10件：Chromium／WebKitで、位置情報を模擬して新宿の候補を検出し、登録した東京へYahoo!で検索することを検証。Windows Playwright WebKitの模擬timestampはmicroseconds相当の値を返すことを実測したため、テスト内だけで日時の単位を補正。本番の古い位置・不正日時の拒否条件は緩めない。実際のiPhoneのGPS精度、屋内・地下・高層ビル街での測位は未検証。模擬位置による検証を実機測定と扱わない。

従来の性能記録は2026-10-01版の測定。今回のGPS取得時間・電池消費をその記録で保証しない。高精度指定は測位機会を改善するための設定であり、実際の誤差の縮小は実機検証が必要。
